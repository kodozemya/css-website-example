# Приклад: Лендінг агенції Positivus

Еталонний розв'язок бою з босом регіону **«Каскади»** (CSS).
Чисті HTML і CSS: без збирачів, препроцесорів, CSS-фреймворків
і **без жодного рядка JavaScript**.

Макет: [Positivus Landing Page Design](https://www.figma.com/design/z5M9wQ65vefFsrgVvNc1Cx/Positivus-Landing-Page-Design?node-id=330-762)

> Це приклад, а не шаблон. Прочитай, зрозумій рішення — і зроби свою версію.

## Як подивитися

Відкрий `index.html` подвійним кліком у браузері.

Шляхи до картинок відносні (`assets/logo.svg`, а не `/assets/logo.svg`) —
саме тому подвійний клік і працює. Абсолютний шлях починається від кореня
сайта, а для файла з диска коренем стає корінь диска — картинки просто
не знайшлися б. Відносний шлях рахується від файла, у якому написаний:
для HTML — від `index.html`, для `url()` у CSS — від `styles.css`. Тут
обидва лежать у корені проєкту, тож запис однаковий.

## Файли

| Файл | Що в ньому |
| --- | --- |
| `index.html` | Розмітка: шапка, вісім секцій, підвал |
| `styles.css` | Стилі; змінні, цеглинки, секції, медіазапити — саме в цьому порядку |
| `assets/` | Логотипи, ілюстрації, фото команди, іконки соцмереж, іконка вкладки |

## Рішення, які варто зрозуміти

### 1. Акордеон «Наш процес» — на `<details>`, а не на JavaScript

У цьому бої JavaScript заборонений, а в макеті є розгортання пунктів.
Виходу два: не робити його зовсім — або згадати, що браузер це вже вміє.

```html
<details class="card step" open>
  <summary class="step__head">…</summary>
  <p class="step__text">…</p>
</details>
```

Браузер сам відкриває й закриває блок, сам керує ним із клавіатури
(Tab + Enter) і сам повідомляє читалці, розгорнуто пункт чи згорнуто.
Коли блок відкрито, браузер ставить атрибут `open` — і CSS на нього реагує:

```css
.step[open] .step__toggle::after { transform: translate(-50%, -50%) rotate(0deg); }
```

Плюс перетворюється на мінус без жодного скрипта.

### 2. Бургер-меню — на одному чекбоксі

Друге місце, де за замовчуванням тягнуться по JavaScript. Тут стан
«відкрито/закрито» тримає `<input type="checkbox">`, а `<label for>`
працює кнопкою — і таких лейблів три: бургер у шапці, затемнення позаду
шухляди й хрестик усередині неї. Усі три перемикають той самий чекбокс.

```css
.burger-menu__checkbox:checked ~ .site-nav { transform: translateX(0); visibility: visible; }
html:has(.burger-menu__checkbox:checked) { overflow: hidden; }
```

Дві деталі, які легко проґавити:

- Чекбокс приховано **візуально**, а не через `display: none`. З `display: none`
  він зник би і з клавіатури, і з читалки — меню перестало б відкриватися
  пробілом. Обведення фокуса тому перекинуто на видимі кнопки через `~`.
- Зачинена шухляда стоїть за краєм вікна через `transform`, але цього мало:
  без `visibility: hidden` посилання всередині лишаються в Tab-порядку,
  і клавіатура провалюється в невидиме меню.

### 3. `backdrop-filter` — на псевдоелементі, а не на шапці

Розмиття під шапкою винесено в `::before`, і це не косметика:

```css
.site-header::before {
  content: "";
  position: absolute;
  inset: 0;
  z-index: -1;
  backdrop-filter: blur(10px);
}
```

`backdrop-filter` (як і `filter` чи `transform`) робить елемент
containing block для всіх нащадків із `position: fixed`. Поки він стояв
на самій `.site-header`, шухляда меню рахувала свої `top/right/bottom`
**від шапки**, а не від вікна — і замість меню на весь екран виходила
смужка заввишки в шапку. На `::before` такого немає: шухляда йому не нащадок.

### 4. `scroll-margin-top` — те, через що якірне меню «наче працює, але не туди»

Шапка липка (`position: sticky`). Якірне посилання прокручує секцію під
самий верх — і її заголовок ховається за шапкою.

```css
:target { scroll-margin-top: 150px; }
```

Один рядок відсуває точку зупинки. Значення має бути **не меншим** за
реальну висоту шапки: тут вона ~110px (падінг 20 + кнопка меню 70 + падінг 20),
тож 150 дає ще й повітря зверху. Помилка на 20px виглядає точно так само,
як відсутність цього рядка, — просто менш помітно.

На вузькому екрані меню їде в шухляду, від шапки лишається логотип із
бургером (~64px) — і відступ теж стає меншим:

```css
@media (max-width: 992px) {
  :target { scroll-margin-top: 90px; }
}
```

**Тут навмисно лишено недоопрацювання.** Значення прив'язане до 992px,
а шухляда починається з 860px. У смузі 861–992px меню ще горизонтальне,
шапка ~107px і може переноситися в два рядки — 90px їй замало. Звузь вікно
до ~900px, клікни пункт меню й подивись сам; потім подумай, як це лагодити.

### 5. Роздільники між кейсами — це межа, а не порожній `<div>`

```css
.case + .case {
  padding-left: 64px;
  border-left: 1px solid var(--color-white);
}
```

Селектор `+` бере кожен наступний кейс після попереднього — тобто всі,
крім першого. Лінія з'являється сама, у розмітці її немає. Порожній `<div>`
заради лінії — це розмітка, що описує вигляд, а не зміст.

У медіазапиті та сама лінія стає горизонтальною: `border-left` вимикається,
вмикається `border-top`.

### 6. Контейнер: чому 1280, а не 1240

У макеті сторінка 1440px, контент починається на x=100 і закінчується
на 1340 — тобто **1240px контенту**. Спокуса написати `max-width: 1240px`
і на цьому заспокоїтись:

```css
.container { max-width: 1240px; padding: 0 20px; }   /* ✗ */
```

Але вище у файлі стоїть `box-sizing: border-box`, і він означає, що
padding **входить** у max-width. Контент виходить 1240 − 40 = 1200px,
а не 1240. Далі помилка тягнеться по всій сторінці: усі картки на 20px
вужчі за макет.

```css
.container { max-width: 1280px; padding: 0 20px; }   /* ✓ 1280 − 40 = 1240 */
```

Перевір лінійкою в браузері: блок «Кейси» має бути рівно 1240px.

### 7. Сітка команди: `min(330px, 100%)`, а не просто `330px`

```css
grid-template-columns: repeat(auto-fit, minmax(min(330px, 100%), 1fr));
```

Мінімум у `minmax()` — це **жорсткий** мінімум: колонка не звужується
нижче за нього ні за яких обставин. З `minmax(330px, 1fr)` на екрані 320px
картка лишалася завширшки 330px і тягла за собою горизонтальну прокрутку
всієї сторінки. `min(330px, 100%)` дозволяє їй впасти до ширини колонки.

Той самий фокус у `minmax(0, 1fr)` у секціях послуг і кейсів: без нуля
довге слово всередині картки не дає колонці стиснутися.

### 8. Обведення фокуса має бути видно на ТЕМНОМУ тлі теж

Найпоширеніша помилка з `:focus-visible` — написати одне правило й забути,
що півсторінки темні:

```css
:focus-visible { outline: 3px solid var(--color-dark); }
```

На білому це ідеально. У підвалі, в «Кейсах» і на темних картках послуг
темна обводка на темному тлі дає контраст **1:1** — фокус фізично є, але
його не видно. Уся нижня третина сторінки стає непрохідною з клавіатури.

```css
.footer :focus-visible,
.cases :focus-visible,
.card--dark :focus-visible {
  outline-color: var(--color-white);
}
```

Перевір просто: натисни Tab до підвалу й подивись, чи бачиш, де ти зараз.

### 9. Два шрифти, бо в Space Grotesk немає кирилиці

```css
--font: "Space Grotesk", "Onest", system-ui, sans-serif;
```

Текст сторінки англійський, тож усе малюється Space Grotesk. Onest тут
на випадок перекладу: шрифт із макета кирилиці не має, а браузер підбирає
шрифт **для кожного гліфа окремо**, а не для всього тексту. Тож щойно
в тексті з'явиться кирилиця, вона дістанеться Onest — найближчому за
характером геометричному гротеску, — а не системному шрифту навмання.

Це не хитрість, а звичайна робота зі шрифтовим стеком. Перевір сам:
постав Onest **першим** — і латиниця теж стане Onest.
